# Jira (Gestão de Bugs e Tarefas)

O **Jira** é uma ferramenta desenvolvida pela **Atlassian** utilizada para gerenciar tarefas, acompanhar o desenvolvimento do projeto e registrar bugs encontrados durante os testes.

É uma das ferramentas mais utilizadas por equipes que trabalham com metodologias ágeis, como Scrum e Kanban.

---

# Conceito Fundamental

No QA, o Jira é utilizado para:

- Registrar bugs;
- Acompanhar correções;
- Gerenciar tarefas;
- Organizar o fluxo de trabalho;
- Facilitar a comunicação entre as equipes.

Cada item registrado no Jira é chamado de **Issue**.

---

# Tipos de Issue

Uma **Issue** representa qualquer item de trabalho dentro do projeto.

Os tipos mais comuns são:

- **Bug** → defeito encontrado no sistema.
- **Task** → tarefa técnica ou administrativa.
- **Story** → funcionalidade baseada em uma necessidade do usuário.
- **Epic** → conjunto de Stories relacionadas.

---

# Principais Informações de um Bug

Ao registrar um bug no Jira, normalmente são informados:

- Título;
- Descrição;
- Passos para reprodução;
- Resultado esperado;
- Resultado obtido;
- Prioridade;
- Evidências (prints ou vídeos).

Quanto mais completo o registro, mais fácil será reproduzir e corrigir o problema.

---

# Fluxo de uma Issue

Cada Issue passa por diferentes estados durante seu ciclo de vida.

Os mais comuns são:

- **To Do** (A Fazer)
- **In Progress** (Em Andamento)
- **Done** (Concluído)

Algumas empresas também utilizam estados como:

- Open
- Testing
- Closed

---

# Boas Práticas

Ao registrar um bug no Jira:

- Utilize títulos objetivos.
- Descreva claramente o problema.
- Informe os passos para reprodução.
- Adicione evidências quando possível.
- Defina a prioridade corretamente.
